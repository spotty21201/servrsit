# Handoff: Designer T-075 (branch `feat/designer/t067`)

## What changed
- **Empty Overview (UX §7.2):** with a connected API and zero servers the roster is replaced by "Let's meet your first server.", the supporting sentence, the support boundary (Ubuntu LTS, existing SSH access and a network path, looks only) and one primary action, **Connect a server**. No marketing, no green checks. "Needs attention" says "No server is connected, so nothing has been checked yet" (never "nothing needs attention"). The Ask bar is hidden because there is nothing to ask about.
- **Compact list, sort, saved preference (UX §5.2):** from 6 servers the roster offers **Cards / Compact list** and **Sort by Needs attention first / Name A to Z / Last check, oldest first**. The preference (view and sort only) is saved in `localStorage` (`servrsit.overview.prefs.v1`). The initial order is computed on entry; later status changes update rows in place and the owner is told "Order is from when you opened this page; statuses have changed since. Update order". Pure logic in `components/overview/listView.ts` with tests; the row component is `CompactServerList` (same information as a card: name link with a whole-row hit area, role, Production label, status badge, main line, observed time, latest failure, action; identity colour only in the icon and left edge, border style dashed/dotted for uncertain/no-data).
- **Stress fixtures:** `fixtures/stressFleet.ts` builds 0 to 20 servers with very long names, roles, package names, versions and mount paths. `/fixtures/overview?n=20&long=1` renders the Overview on them ([FIXTURE DATA]). `/plans/fixture-plan-long` is a plan with a 70+ character server name and long package versions. Server detail is stressed in the audit by serving the same fleet through an intercepted `/api/fleet`.
- **Loading and API-down on every screen:** Findings, Activity, Settings and Baselines had no loading text and no retry; they now show "Loading …" and a failure panel with **Try again** that says what the failure does not mean ("This does not mean there are no findings"). Plan, Operation and Server detail loading and failure states now carry an `<h1>` (axe `page-has-heading-one` found them without). `LoadFailure` renders its title as the page `<h1>` unless told otherwise. Fixture screens can be previewed in these states with `?state=loading` or `?state=error` (`lib/fixtureState.ts`; fixture clients only, real clients never read it).
- **Defect found by the stress fixture and fixed:** long server names overflowed the page by 181 to 258 px at 390 and 320 px in the "Needs attention" list (`white-space: nowrap`). Names and titles now wrap.
